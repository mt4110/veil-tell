# npm 導入検証の記録ひな形

[設計書の導入検証](design.md#手軽さと需要を確かめる)に沿って、開発に関わっていない npm プロジェクトの保守者3人に1枚ずつ記録してもらう。導入案内は [依頼文](npm-onboarding-invitation.md) の README リンクを入口にする。対照入力は通常実行の確認後に使う。

## 参加者用　1人1枚

- 参加者ID（A・B・Cのいずれか）　　　　
- 実施日　　　　
- Node.js と npm の版、ランナー　　　　
- 更新した依存と変更前後のバージョン　　　　

README を開いてから記録を開始。CI の待ち時間はジョブのキューと実行にかかった時間のうち、待っていた分を記入してください。操作と待機が重なった時間は経過時間に二重計上せず、中断の時間は別に記録してください。分からない欄は「未計測」、試していない欄は「未実施」で構いません。

| 工程 | 結果または途中まで進んだ内容 | 操作（分） | CI待ち（分） | 要約・JSON の確認結果 |
| --- | --- | --- | --- | --- |
| README から導入して基準候補を採取 | | | | 採取時の終了コード、候補の宛先 |
| 基準候補をレビューし、ベースに保存 | | | | 宛先の用途をどう確認したか |
| 通常の依存更新 PR | | | | 要約の表示、`run_status.exit_code`、`comparison.added` |
| 同じ PR で未登録 CONNECT の対照 | | | | 要約の宛先、`child_status.exit_code`、`run_status`、該当する宛先の `result` |

- README を開いてから通常実行の要約と JSON を確認するまでの実経過（分、CI待ち込み）　　　　
- README を開いてから対照の要約と JSON を確認するまでの実経過（分、CI待ち込み）　　　　
- 中断した時間（分）　　　　

### 最初に詰まった箇所

- 工程、画面・コマンド、表示されたエラーの該当行　　　　
- そこで何を期待し、何が分からなかったか　　　　
- 自力で解決した・助けを受けた・中断した。解決した場合は何を変えたか　　　　
- 追加で見た案内や人から受けた助言と、その時点　　　　

### 実行結果を見た後

- 対照の要約で見つけた宛先　　　　
- この依存更新をどう扱うか、承認する前に何を確かめるか　　　　
- 次の依存更新に使った・外した・まだ次の更新がない。使った箇所または外した理由　　　　

共有は上の記録だけで足ります。実行リンクは共有可能な場合だけ添えてください。認証情報や非公開の宛先、ログや JSON の全文は送らず、必要な項目だけ転記してください。

## 主催者用　3人分の集計

最初の成功は、通常実行の要約と JSON で veil-tell の `0` を確認した時点。暫定目標は、3人のうち2人以上が個別の手助けなしで20分以内に最初の成功へ到達すること。20分は CI 待ちを含む実経過で判定し、操作時間も併記する。集計には、GitHub Actions の **Summary** と **Artifacts** の JSON を使う。通常は `run_status.exit_code: 0` と空の `comparison.added` を照合する。対照は `run_status.exit_code: 21` と `new_destination`、試験宛先の `blocked`、`child_status.exit_code: 0` を照合する。合成の対照入力を提供すること自体は個別の手助けに含めない。

| 参加者 | 通常 `0` と対照 `21` の確認 | 通常成功までの実経過・操作・CI待ち（分） | 個別の手助け | 最初の詰まり | 次の更新で使ったか |
| --- | --- | --- | --- | --- | --- |
| A | | | | | |
| B | | | | | |
| C | | | | | |

途中までの記録も残し、手助けなしで20分以内に成功した人数と、両ケースを完了した人数を集計する。完遂できなかった人がいれば、最初に詰まった箇所を手順の見直しに使う。
